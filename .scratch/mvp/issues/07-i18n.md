# 07 — i18n for en / it / ro in SvelteKit

Type: research
Status: resolved
Blocked by: —

## Question

Research internationalisation for SvelteKit 5 targeting **English, Italian and Romanian**, under
the "translate-only, one shared economy" decision.

- **Library**: current options for SvelteKit 5 (e.g. `svelte-i18n`, Paraglide, built-in approaches)
  and which fits a game with large text content plus 60 Event Cards.
- **Content organisation**: how UI strings and Event Card text are structured so translation is
  mechanical and testable; how missing keys are caught.
- **Routing**: locale routing vs a locale switch, and the effect on SEO and deep links.
- **Formatting**: currency, number and date formatting given one economy shown in en/it/ro.
- **Authoring**: what a translator needs, and whether the 60 cards can be translated without
  developer involvement.

Output: a recommendation with a concrete content-layout proposal.

## Answer

Resolved. Full findings and sources: [`research/07-i18n.md`](../research/07-i18n.md).

**Library — Paraglide JS.** Use `@inlang/paraglide-js`, the **official SvelteKit i18n integration**
(`npx sv add paraglide`). It is compiler-based, fully typed (`emitTsDeclarations`), tree-shaken, and
SSR-safe on Vercel via request-scoped `AsyncLocalStorage`. Its inlang companions (Fink editor, inlang
CLI, `missingTranslation` lint rule) are what make the 60 cards translatable without developers.
`kaisermann/svelte-i18n` is store-based, unmaintained-ish (v4.0.1, ~2 years old; README flags a
rework) and has no compile-time key safety or translator tooling. Minimal runes-native libs
explicitly disclaim large text volumes. SvelteKit ships no i18n library of its own.

**Content layout — structural deck + one text catalog.** Keep `content/cards/*.json` **language-neutral**
(ids, stage, concept, weight, art, effects) and put all prose in `messages/{locale}.json`. Card text
uses **deterministic keys derived from immutable card/choice ids**:
`card_042_situation`, `card_042_choice_save_label`, `card_042_choice_save_feedback`. Do **not** embed
per-locale strings in the card JSON — inlang/Fink cannot read them and every edit becomes a developer
task. This forces ticket **03** to drop its "locale strings for en/it/ro" field in favour of the key
convention.

**Missing keys — three CI gates.** (1) `sv check` / TypeScript catches a code-referenced key that is
absent (typed generated functions). (2) `npx @inlang/cli lint` with
`messageLintRule.inlang.missingTranslation` raised to **`error`** catches an `en` key untranslated in
`it`/`ro`; add `inlang validate`. (3) A Vitest deck-integrity test enumerates every card/choice and
asserts its keys exist in all three locales, that interpolation parameters match across locales, and
that no orphan `card_*` keys exist — the gap Paraglide cannot type-check for dynamically derived keys.
(The inlang PR action "Ninja i18n" is deprecated — use the CLI.)

**Routing — locale-prefixed URLs + cookie.** `strategy: ["url", "cookie", "preferredLanguage",
"baseLocale"]` with the standard prefixing (`/game`, `/it/game`, `/ro/game`) via the generated
`reroute` (in `src/hooks.ts`) and `paraglideMiddleware` (in `src/hooks.server.ts`, also injecting
`%lang%`/`%dir%`). Deep links carry their language; `setLocale()` is a full document navigation that
preserves the path; `generateStaticLocalizedUrls()` feeds hreflang/sitemaps. Locale is **presentation
only** — it must never be persisted into run data or feed the seeded RNG, because the economy is shared.

**Formatting — one currency, three number systems.** Fix the world currency code (recommended `EUR`)
and format with `Intl.NumberFormat(locale, { style: "currency", currency: "EUR" })`, **always passing
the app locale explicitly** (omitting it uses the runtime locale and breaks SSR). Result: `€1,234.50`
(en), `1.234,50 €` (it/ro). Model in-game time as `{year, month}` and render month names with
`Intl.DateTimeFormat` pinned to `timeZone: "UTC"` — no real dates, no DST/ICU drift. Use `plural`
variants (Romanian has `one`/`few`/`other`), memoize `Intl` instances, and snapshot-test formatters so
ICU changes fail loudly. Flagged product choice: showing EUR to `ro` users is a fiction of "one
economy"; the alternative is a neutral in-game currency — either way `currency` must not be
locale-dependent.

**Translator workflow.** Writer authors `messages/en.json`; `inlang machine translate` drafts it/ro;
a human reviews in **Fink** (web CAT editor; beta, with direct-JSON editing as fallback); CI blocks
merges on the lint + deck tests. Provide per-card context via a generated
`docs/translation-brief.md` (stage, concept, what each choice does, teaching point, tone, glossary of
the eight Concepts, mobile length limits) so a translator never needs to read code.
